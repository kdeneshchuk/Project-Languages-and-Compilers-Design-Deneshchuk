No other AI tools were used.

======================================================================
2. HOW I WORKED
======================================================================
I did not ask for the whole project at once. I first discussed the language
design, chose the features myself, and only then built the project in small
pieces: grammar, AST classes, lexer, parser, CLI, tests, README. Each piece
of code was pasted into my VM, run by me, and its real output was compared
with what the AI predicted. Where they differed, I used the real output and
asked what was wrong. I asked for explanations of every piece of code
("explain this part in detail") before moving on.

5. WHAT I DECIDED MYSELF
======================================================================
- the whole language concept: a story-like language, the words always /
  once / changing, is / was / became, when / otherwise / end / tell,
  a full stop ending each sentence
- "simple enough that I do not get confused in it" (I rejected prefix
  notation and gutter blocks)
- emoji as synonyms for yes/no and for the comparisons
- renaming the comparison words to equals/differs, after the AI noticed
  that "is" was used twice
- no comments in the language
- the name Telly
- yes / no kept as synonyms of the thumbs emoji
- tell takes a single value
- the modular file layout
- building the optional VS Code extension
- committing the example program

======================================================================
6. WHAT I CHANGED OR CORRECTED
======================================================================
- I did not trust the expected line:column values blindly: I compared every
  .expected file with a table of expected positions and ran the code to
  see the real output.
- Long pasted scripts were damaged by the terminal twice; this produced a
  duplicated block of methods in parser.py. I found it with grep -c and
  grep -n and cut the duplicate.
- The INT_MAX cleanup was misunderstood: I moved the constant out of the
  class while check_range still used self.INT_MAX. The test runner
  reported 59 of 82 tests failing; I fixed the reference.
- A 5000-digit number crashed the compiler with a Python ValueError. I
  reproduced the traceback first, then added the digit-length check.
- I also asked for the same audit from ChatGPT (second tool) and compared
  its remarks with the first one.

======================================================================
7. WHAT THE CHATGPT REVIEWS CHANGED
======================================================================
- The overflow check after "became" needs a symbol table, so stage 1
  checks only a literal next to its declared type (grammar.ebnf updated).
- parse_compare_op() and parse_boolean() became separate functions, to
  match "one function per grammar rule".
- A claim that grammar.ebnf had "*" instead of "_" was a formatting
  artifact of the chat; I checked the file (grep) and it was correct.
- A claim that ai_usage.txt was missing was right at that moment; this
  file is the fix.
